# V2 规划与数据结构

## 一、目标与边界

V2 的目标是提供可在不同 Mac 上双击使用的本地 `.app`。用户无需安装 Python、虚拟环境或输入终端命令。

V2 不把名单、答案和答题卡模板混为一个文件，也不把“模板制作”混入日常阅卷界面。

## 二、四类核心数据

### 1. 答题卡模板包

模板包描述“如何读取一张答题卡”，而不保存某一次考试的学生或正确答案。它至少包含：

- 模板名称、唯一 ID、版本、状态；
- 空白答题卡参考图；
- 定位点定义；
- 考号和客观题/教师得分区位置；
- 题目、选项和可配置评分分项；
- 模板测试结果及批准状态。

一个模板包可被多次考试复用。模板包只有通过测试后才能用于正式考试。

### 2. 评分结构

评分结构属于模板包，但不固定为 12 个分项。每个分项定义：

- 内部 ID 与显示名称；
- 满分；
- 由哪些题目或得分框组成；
- 是否允许空白；
- 汇总方式。

当前 V1 的 12 分项将作为第一个兼容配置导入，不被硬编码为 V2 的唯一模式。

### 3. 正确答案

正确答案属于“单次考试”，而非永久属于模板包。

模板包会自动生成可录入的答案表（题号、选项范围、分项和分值均预填），用户填写正确答案后导入或在 App 内确认。正式来源应是结构化答案表；DOCX 仅在采用固定表格模板时支持自动导入，任意排版的 DOCX 必须经人工确认后才可生效。

### 4. 单次考试

单次考试是日常使用的工作单元，绑定：

- 一个已批准的模板包版本；
- 本次正确答案版本；
- 本次导入的学生名单快照；
- 用户选择的照片目录；
- 本次结果和导出记录。

照片与导出的成绩文件暂时继续放在用户选择的照片目录中。App 程序包与考试数据分离。

## 三、模板制作器与日常阅卷 App

模板制作器应是独立工具，不放进日常阅卷主界面。

模板制作器的流程：

1. 导入空白答题卡；
2. 设置定位点、考号区、题目区和得分区；
3. 定义题目选项与评分结构；
4. 自动生成答案录入表；
5. 导入真实拍摄测试样张；
6. 查看定位后整卷与区域裁切结果；
7. 记录测试结果并批准模板包。

测试样张至少覆盖不同手机、不同拍照/文档模式、原图/增强/黑白模式、不同桌面背景、光照、阴影和轻微透视偏差。

## 四、当前阶段优先级

### 必须

1. 独立 V2 工程，保护 V1；
2. macOS `.app` 打包原型，分别验证 Apple Silicon 与 Intel 策略；
3. 单次考试建立向导；
4. 学生名单导入、列校验和本次考试名单快照；
5. 模板包和答案表的数据契约；
6. 模板测试与定位质量检查流程。

### 应当

- 已完成扫描再次点击时的轻量提示；
- 导出前显示 OK/CHECK 汇总；
- 用户可见的模板包备份/导入。

### 暂缓

- 跨电脑继续同一批照片的人工审核；
- 永久人工修正历史；
- 文件哈希去重；
- Windows 版；
- 多用户、云端或账号体系。

## 五、迁移与打包原则

- 先交付完全本地的 macOS `.app`；
- App 内置运行环境和依赖，用户不接触 `.venv`；
- 根据依赖的原生架构，优先提供 Apple Silicon 与 Intel 两个安装包；
- 用户的照片、名单、模板包和导出结果不放在 `.app` 内；
- 更新 App 不应覆盖考试数据。
