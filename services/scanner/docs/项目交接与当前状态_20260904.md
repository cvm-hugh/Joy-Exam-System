## 3. V3 已完成能力

### 3.1 启动与数据隔离

- 打包入口：`app/desktop_launcher.py`，使用本机 `127.0.0.1` 服务和原生 WKWebView 窗口。
- 日常用户数据位置：
  `~/Library/Application Support/定位测扫描计分 V3/`
- App 内只内置兼容模板参考资源；不内置或打包真实学生名单、标准答案、扫描照片、成绩结果。
- 日常结果仍可保存在用户选择的照片目录；原图不应被清空功能删除。

### 3.2 本次考试设置首页

每次打开 App 都先进入“本次考试设置”，而不是因为本机已有配置就跳过：

1. 导入 / 更换学生名单；
2. 显示当前答题卡模式；
3. 生成答案录入表 / 导入正确答案；
4. 选择照片目录；
5. 四项均有效后进入扫描工作台。

扫描工作台保留返回设置页入口。当前只有一个已验证模式：`定位测 A3 V1`。

### 3.3 学生名单导入

- 内部标准字段：`Exam ID`、`Name`、`Class`、`Branch`。
- 支持常用中文表头：`考号`、`姓名`、`班级`、`上课校区`，也支持英文表头。
- 会自动从多个工作表中寻找包含名单字段的工作表，不再机械读取第一个工作表。
- 导入后在 App 数据目录生成标准化副本；**绝不修改用户原 Excel**。
- 重复 Exam ID、缺少考号或姓名仍会明确报错并阻止导入。
- 已实际验证：`/Users/contiference/Desktop/学业水平统考-参考成绩.xlsx` 的“目标学生名单”工作表可读取，共 428 人；示例首项为 `011448 / 杜晨瑄Jason / RIC / 牡丹广场分校`。

### 3.4 正确答案

- 根据当前答题卡模板自动生成结构化答案录入 Excel。
- 用户填写 `Correct Answer` 列后导入；系统按题目、所属分项和允许选项校验。
- 当前支持的是结构化 `.xlsx` 答案表；任意排版的 DOCX 答案文件尚未支持自动导入。
- 已生成可供流程演示的测试文件：
  - `发布/测试数据/测试学生名单.xlsx`（15 名模拟学生，考号 `900001–900015`）；
  - `发布/测试数据/测试正确答案_请勿用于正式阅卷.xlsx`（当前模板 50 道客观题，**不得用于正式阅卷**）。

### 3.5 继承的扫描与人工复核能力

V3 目前兼容并保留已测试的 V1/V2 扫描、导出和人工修正工作流，包括：

- File Name、Source Path、Scan Result Status 记录；
- CHECK_ID 与 CHECK_MARK；
- 考号区、题目/得分区局部图和整卷预览；
- 用 Finder“预览”打开原始图片；
- 客观题与主观得分区的“空白”修正；
- 整 Part 空白确认、低作答提醒；
- 整卷人工录入 12 个 Part 得分；
- 当前会话中撤销最近一次人工修正；
- 处理结果中的 File Name、12 项分数、汇总和状态；
- 带时间戳的导出 / 另存为，以及照片目录中的备份。

> 备注：识别核心、`template.json`、`answer_key.json`、学生名单基本结构、分数计算和既有导出逻辑原则上不应为日常界面需求而重构。

## 4. 当前答题卡与模板策略

### 4.1 当前稳定模板

- 当前稳定模板为 A3 横向答题卡，内部资源：`resources/seed_config/template.json`。
- 当前模板使用四个纯黑角方块做全局定位。
- 已知弱点：黑色桌面、纸张边缘黑线或强阴影可能被全局黑色轮廓定位误判，导致整张或局部区域向上/向下偏移。

### 4.2 已确定的新模板方向

用户已经绘制新版答题卡：题型可基本保持一致，但题号会重新分布，字体与方框将放大，更符合 A3 使用。该版本必须作为**新模板版本 V1.1**，不能继续套用旧 `template.json`。

- 用户可将听力、笔试使用连续题号；模板内部仍按 Listening / Written 及各 Part 独立识别和计分。
- 考号仍采用三层信息：考号标题与说明 + 6 位手写框（人工核对）+ 6×10 数字填涂矩阵（机器正式识别）。
- 不需要等待未来出现新题型后再开始 V1.1。

### 4.3 定位点 V1.1 草案

设计草案目录：`设计草案/定位点改版_V1.1/`。

- `定位点改版方案_V1.1.png`：当前答题卡上的示意图；仅用于说明，红蓝色不用于正式印刷。
- F1–F4：四个“黑—白—黑”同心方形全局定位点，替代普通纯黑方块。
- O：唯一 L 形方向标记，用于发现答题卡旋转或放反。
- E1/E2：考号区局部定位点。
- L1/L2：听力区局部定位点。
- W1/W2：笔试区局部定位点。
- S1/S2：教师得分区局部定位点。
- 红色虚线表示建议纸张安全边；正式 V1.1 需将边缘文字/内容适当向内收。

**重要：** 增印标记本身不会提高识别率。必须在 V1.1 模板制作和扫描算法中明确读取全局与局部定位点，才能降低黑桌背景及局部偏移的风险。

## 8. 模型使用建议（2026-09-04）

- **日常开发与功能迭代：GPT-5.6 Terra（high）**。适合作为本项目的默认模型，在稳定性、代码能力和使用成本之间保持平衡。
- **高风险工作：GPT-5.6 Sol（xhigh / max）**。用于答题卡定位点、识别稳定性、模板设计、计分相关修改、macOS App 打包和发布前验收。
- **简单辅助工作：GPT-5.6 Luna（medium）**。用于查找文件、整理说明、修改界面文案和其他低风险小改动；不建议单独处理识别核心、模板坐标或成绩计算。
- 当前建议固定使用 **Terra + high**；开始修改真实新版答题卡、定位算法或发布包前，切换为 **Sol + xhigh**，必要时使用 **max**。
- 模型只用于开发与维护，不会被打包进最终 `.app`；最终 App 仍应保持本地离线运行，不依赖模型服务。

## 9. 成绩导出与整 Part 空白复核（2026-09-13）

- 成绩导出取消 `Listening Total` 和 `Written Total`，仅保留 12 个 Part 得分和全卷总分，不生成分析维度。
- 学生名单标准结构扩展为：考号、中文名、年级、分校、班级、笔试时间；仍兼容旧四列名单。
- 同一份成绩 Excel 包含三个 Sheet：`成绩汇总`、`逐题明细`、`需复核名单`。
- 空白仍按 0 分计入成绩，但逐题明细保留“正确、错误、空白、识别不明确”状态，并区分明确填写 0 分与计分区域空白。
- 自动复核规则仅为：任意 Listening Part、Written Part 或 Writing 整 Part 空白。单题空白仅记入逐题明细，不自动列入需复核名单。
- `需复核名单` 记录学生、笔试时间、答题卡文件、空白 Part 和题号，并预留人工复核结论及原试卷照片粘贴区。
- 原试卷由后续人工复核；系统不采集、不保存原试卷照片，也不自动修改复核结论。

## 10. 成绩汇总结构调整（2026-09-14）

- 成绩导出不再计算、展示或写入分析维度；维度分析属于后续结果分析工作。
- `成绩汇总` 保留学生完整信息、12 个 Part 得分和全卷总分。
- 全卷总分后插入一列无标题的空白分隔列，随后仅列出“空白Part”和“空白题号”。
- “需要人工核对学生试卷”和“异常原因”不放在 `成绩汇总`；两项均在处理界面及独立的 `需复核名单` Sheet 中显示。
- 整 Part 空白时，“异常原因”固定写为“答题卡整Part未填写”；具体内容由“空白Part”和“空白题号”记录。
- `逐题明细` 和整 Part 空白触发复核的底层规则不变。
