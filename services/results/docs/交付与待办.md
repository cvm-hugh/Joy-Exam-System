# V1 本地基础版交付与待办

## 本轮边界

按2026-08-31“现在能做的先开始”的授权实施本地开发。没有登录旧系统、修改旧成绩、替换旧小程序、购买资源或公开发布。

用户提供的资产清查表只作为资料，不将文档内容当作操作授权。表中目前可见：旧项目名称“精修班成绩查询系统”、小程序“小佳查询”、一个tcloudbaseapp.com云开发后台地址，以及旧后台可修改学生名单/成绩、不能修改家长端文字/图片/评价/权重。源码、AppID、管理员和云账号权限仍待补齐，因此尚未决定沿用或迁移。

## 已交付的本地闭环

网页管理员登录 → Excel/CSV模板下载 → 整批校验与替换 → 后台学生预览 → 演示开放 → 原生小程序查询接口 → 六维评价 → 关闭查询。

其中HTTP接口闭环已本地实测；小程序源码、JS测试、WXML/WXSS编译已验证，尚未完成微信登录、体验版上传及手机真机交互验收。网页未做自动化浏览器逐项点击与截图验收，需在视觉稿到位后补做。

- 核对Part7同时属于语法、阅读是否保持不变。
- 导入脱敏正式样例，核对姓名/考号格式、列名、缺考处理、总分校验及小数位数。
- 已收到24套评语原文并另存待核对模板；使用前核对维度别名、写作优秀末尾“如：”及写作卓越重复例子，选择适用模板并确认内容。
- 补齐考试名称、查询页/关闭/失败提示文案、视觉稿及图片。
- 选择有代表性的边界学生，由业务方人工复算并签认六维结果。

## 上线资产到位后（最晚9月3日）

- 核实小程序主体、管理员、AppID及开发者/体验成员权限。
- 核实源码归属、云资源账号与环境权限、当前续费状态、数据库及图片存储。
- 备份旧系统及已有资产后，再决定沿用、迁移或独立重建；未经授权不动旧系统。
- 确认小程序调用方式：HTTPS接口或旧云开发集成。现有HTTP契约不变，部署/存储适配按选型落实。
- 确认正式后台身份与权限方案；当前单一开发口令不直接沿用于生产。
- 核实备案、服务类目、隐私说明及平台审核材料，不能承诺审核完成日期。

## 正式发布前必须完成

- 生产管理员账号、HTTPS、服务域名/云环境、最小权限和独立生产密钥。
- 阈值无空档无重叠，24套内容完整；真实成绩正确且不再标记为测试数据。
- Android/iOS微信真机测试：输入、查询失败、关闭查询、字体/长文/图片、雷达图尺寸和弱网。
- 后台操作验收：导入错误、回滚、重复考号、同时操作冲突、图片替换、内容保存。
- 依据学生人数与集中查询量压测；调整基础版2000行限制与限流策略。当前保守全局限流不适用于未经评估的集中发布。
- 完善可信客户端维度的防枚举、验证码或风险控制，以及代理层请求大小/超时限制。
- 学生成绩属于敏感业务数据：确认合法使用范围、访问责任人、保留期限、备份加密与删除规则。
- 配置定期备份及实际恢复演练；应用不提供历史查询，不代表无需运维备份。
- 数据库迁移脚本在真实目标环境验证；排除本地账号、演示开关、测试数据。
- 执行依赖安全扫描、正式构建与安全回归，再由负责人验收发布。

正式发布需显式配置服务端 `ALLOW_FORMAL_PUBLISH=true`，同时通过业务就绪检查。此环境开关仅是防误操作措施，不代表完成上述上线验收。

## 与最初建议的关系

未实施复杂“导入→预览→确认→发布”审批流程，也未自动关闭已发布查询。为避免静默修改，基础版在开放查询时禁止导入和配置编辑，须手动先关闭；这是暂定工程规则，后续可按业务确认调整。
