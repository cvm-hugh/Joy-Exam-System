# 考试结果查询系统 · V1 本地基础版

截至 2026-09-15 的完整功能、报告版式、资格判断、六维显示、批量导出、安全边界与恢复规则，统一见 [`docs/阶段版本基线_2026-09-15.md`](docs/阶段版本基线_2026-09-15.md)。早期记录如与该基线冲突，以阶段基线和自动化测试为准。

本项目独立于上级目录原有软件。管理后台是网页；家长端是原生微信小程序。尚未上线，没有访问或修改旧系统。业务方已在本地成功导入学生名单；不要在此数据库运行会替换名单的测试。

## 快速开始

需 Node.js 22.13 或以上版本（已在 Node 22.16 验证）。在此目录运行：

```sh
npm ci
npm run setup
npm run dev
```

打开终端显示的本地网址，默认 `http://localhost:3000/`。后台管理员口令在 `.local/admin-login.txt`，初始化时随机生成，不在源代码或页面中公开。首次初始化后若服务已启动，请重启使 `.dev.vars` 生效。

日常使用可运行 `npm run build && npm run desktop:build` 生成 `output/考试结果管理.app`。双击应用会自动启动本地服务并在原生窗口中显示后台；关闭应用时会同步停止由它启动的服务。运行日志保存在 `.local/logs/desktop-server.log`。

不要把 `.dev.vars`、`.local/`、`.wrangler/`、真实成绩文件或账号凭证提交到代码仓库。

## 现在可用

- 管理员口令登录、HTTP-only会话、退出登录、登录限流和后台写操作来源校验。
- 网页工作台、当前考试信息、发布状态和资料待办。
- 教学支撑与行政服务分组。先在“试卷模板”配好套卷，再由行政选择整套配置、下载Excel/CSV成绩表。虚构样例及一键加载入口已移除。
- 考号保留前导零；必填、重复考号、非数字、负分、超满分、公式、总分不一致校验；错误指出行号。
- 合并版可直接接收阅卷结果及原始名单全部业务列；`S + 5位` 学号自动对应 `0 + 5位` 考号，无需人工重新导入成绩。
- 成绩整批事务替换；失败保留旧数据；乐观版本检查避免并发覆盖；只保留最新一批可查询成绩。
- 后台学生列表、姓名或考号单项检索、九页结果预览、六维雷达图和评价预览。
- 六个维度独立阈值编辑，24套评价每套3段文字编辑，段落标题及固定文案编辑。
- 套卷统一包含Part结构、满分、维度关联、等级分档、24套评价及图片引用；可更新默认版本、重命名、另存、删除。编辑默认收起；保存模板不会追改当前学生结果。
- 卷内“评价管理”仅含评语、标题、图片和Excel批量导入；旧版分析、评价、阈值模板保留，可在对应编辑区复制到套卷。复制旧分析模板不带入旧阈值。
- 行政导入时一次启用整套配置；已保存考试保留独立快照。下载/导入校验模板版本，写入事务再次检查版本，防止与同时编辑的模板混搭。
- 等级编辑上限在上、下限在下；相邻边界联动。下限均含，上限除最高等级1外不含，没有单独包含上限勾选框。
- 入口、内容、封底三个页面的编辑与预览左右配对，入口可切换开放／关闭效果。封底底图和选填二维码独立上传；各图片入口标注制作尺寸。PNG/JPEG/WebP，单图2MB以内，图片存储与业务记录分离。
- 成绩导入默认选中“学业水平统测｜英语2608”，选择即采用，无需刷新。可直接导入阅卷系统三 Sheet 成绩文件；尚有名单外考号或原卷复核项时拒绝替换正式批次。提供逐人零星补录：自动合计，确认后只追加，重复考号不覆盖，沿用当前批次计算配置。
- 关闭查询／演示开放；正式发布在本地默认被服务端禁用。
- 原生微信小程序查询页、结果页、Canvas六维雷达图、三段文字评价、关闭查询和错误提示。
- 查询接口只返回本学生六维结果，不返回Part原始成绩、总分、排名、平均分、其他学生或历史记录。
- 固定九页、390 × 844 的所见即所得 PDF；页面只使用边框、不使用投影。支持按所选学生导出、分档打包。六维真实系数工作簿沿用原始名单列和原值，再追加 Part、总分、六维总得分与两位截断系数。

## 快速试用

1. 用本地管理员口令登录后台。
2. 已有当前学生时无需重新导入，直接去“学生预览”。尚无套卷时：教学支撑→试卷模板→建立首套试卷模板→填写名称→保存本套卷。已有套卷时选择即自动载入，可点击“从当前试卷模板复制新建”建立独立副本。
3. 换试卷时，行政服务→成绩导入→选择配套试卷→下载对应成绩表→校验并替换。再到“学生预览”点击“查看六维评价”。
4. 到“配置与发布”，打开“结果查询演示预览”右侧开关，仅供开发测试。左侧按钮仅展示入口效果，不开放查询。
5. 小程序导入方法见 `miniprogram/README.md`。
6. 试用结束点击“关闭查询”。

新增模板操作说明见 `docs/模板与家长端使用说明.md`。原3名虚构学生不在当前名单中，当前名单完整保留。自动化测试的虚构数据仅位于tests目录。

## 已落实的业务规则

- 初始Part配置在 `lib/domain.ts`；后续由套卷的“题型与满分”管理。初始试卷满分80，维度满分依次15、10、17、10、20、15。
- Written Test Part7在语法与阅读分别参与计算，总分只计一次。六维满分之和87不代表试卷满分。
- 等级比较通过精确十进制乘法比较得分与“满分×阈值”，始终使用完整原始系数，不受展示取值影响。
- 页面与雷达图使用直接截断至小数点后1位的系数×100定位；除写作可显示0.0外，其余五维最低显示0.3。低分保护不参与等级和资格判断。
- 2026-08-31确认的连续分档：卓越[0.8,1]，优秀[0.6,0.8)，良好[0.4,0.6)，待加强[0,0.4)。卷内“系数阈值”提供逐维编辑和六维统一采用入口。
- 旧配置及旧模板不会被升级自动覆盖。若仍使用原先带空档区间，对未覆盖系数继续显示“等级待确认”；需载入连续分档、保存或应用后才生效。
- 初始评价是明显标注的测试占位文本，不由AI临时生成正式评价。

## 本地基础版的暂定工程规则

以下用于先跑通流程，不宣称已经得到业务方最终确认；资料到位后核对：

- 修改考试配置或替换成绩前，必须先手动关闭查询；不隐式自动关闭。这保证发布中的内容不被静默修改。
- 总分必须精确等于所选套卷不重复的Part得分之和；最多支持4位小数得分，不接受Excel公式。若正式成绩表包含公式，先粘贴为数值。
- 姓名允许汉字及间隔点，考号允许字母、数字、下划线、短横线；仅去除两端空白。
- 当前单批上限2,000名学生、文件3MB。这是基础版容量限制，不是最终业务容量承诺。
- 图片移除操作仅移除配置引用，不删除底层文件；上线前按保留策略增加清理任务。
- 基础版使用保守的全局查询限流（120次/分钟）和考号限流（12次/分钟）；生产前必须按真实并发及可信客户端标识重新设计/配置，不能直接用于全校集中发布。

## 验证

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

测试均使用独立内存SQLite，覆盖业务计算、导入、事务回滚、认证、查询隔离、发布控制和小程序逻辑。

上面的冒烟测试仅登录并只读检查模板下载、学生结果预览、配置是否保持不变；不导入、不保存配置、不切换发布状态。全流程写入测试仅在独立内存数据库运行。

微信WXML/WXSS本地编译器检查通过不等于微信真机验收；尚需AppID、测试域名和体验成员权限。

## 项目结构与后续部署

```text
app/                 网页入口、API路由
components/admin.tsx 网页后台与后台结果预览
lib/domain.ts        默认试卷、动态分析规则校验、精确判级、结果白名单
components/paper-workspace.tsx 教学套卷库与卷内配置编辑
lib/templates.ts     配套试卷及旧版组件模板定义、兼容校验
lib/evaluation-importer.ts  24套评价Excel生成、上传校验
lib/importer.ts      Excel/CSV校验、模板生成
lib/store.ts         数据存储适配层、事务与版本保护
lib/api.ts           管理接口和小程序查询接口
lib/security.ts      认证与来源校验
db/、drizzle/        数据结构与迁移
miniprogram/         原生微信小程序源码
tests/               自动化测试
docs/                接口与后续验收清单
```

网页按Sites技能生成，当前数据库/图片存储为本地模拟D1/R2（文件位于`.wrangler/`），未创建远程资源。后端业务逻辑与路由及存储适配层分开。旧系统账号、源码和云资源到位后再确定保留云开发、迁移或重建；如选腾讯云，需要实现对应存储/部署适配，不能把本地模拟环境当成已完成腾讯云部署。

小程序暂用游客AppID，正式环境开关默认关闭。应用运行时无需OpenAI API或AI评价服务。
