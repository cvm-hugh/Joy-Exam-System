# 佳音考试管理

当前稳定发布版本：**V2.0（2.0.0）**。该版本集中阅卷状态操作、拆分 API 请求处理与 Excel 导出辅助代码，并加入 Python 源码静态编译检查。说明见 `docs/代码整理_2026-10-04.md`、`docs/V2.0发布说明_2026-10-04.md`。

Windows 桌面预览版：**2.1.0-beta.2**，目标为 **Windows 10 / Windows 11 x64**。提供 EXE 安装程序和完整目录 ZIP，内置运行环境，使用者无需另装 Python/Node；实际 Win10/11 人工验收待进行。V2.0 稳定版的标签和发布材料继续保留。安装、数据与构建说明见 [Windows 桌面预览版](docs/windows-desktop.md)。

自 2026-10-02 起，本项目是唯一后续维护主线。阅卷和结果管理的源码、测试、配置、桌面入口与构建脚本均在此目录内维护；原有独立 App 保留为历史版本与回退材料。

正常工作流程为“名单 → 阅卷 → 结果管理”。阅卷端完成图片复核后，通过带临时令牌的本机内部通道直接交接名单和成绩；结果端仍使用严格导入器验证，Excel 导出保留为可选备份。

年级作为选填参考信息：初一至初三统一为七至九年级，空白、斜杠和未知显示为待补充，其他写法保留并提醒核对。年级异常不会阻断导入、交接或报告导出。导出前列出分校、班级、笔试时间和年级的待完善信息，可返回名单补充或继续导出；Excel 附有“信息待补充”和“原始名单信息”，保留原始内容与当前补充信息。规则见 `docs/参考信息与导出补充提醒_2026-10-03.md`。

资格结果是套卷固定内容，默认按总分线和六维线计算并显示，不再需要勾选启用。旧模板的关闭标记兼容读取，分数线及文案保留。跨机导入套卷后可“保存并用于当前考试”；已保存套卷可“用于当前考试”，应用时保留学生名单和原始成绩。说明见 [资格结果默认显示](docs/资格结果默认显示_2026-10-07.md)。

## 项目结构

- `desktop/`：macOS 桌面入口与 `desktop/windows/` 下的 Windows 桌面入口。
- `services/scanner/`：阅卷源码、资源、数据模型与测试。
- `services/results/`：结果管理源码、数据库结构、报告、小程序与测试。
- `scripts/`：统一安装、启动、检查、测试和构建入口。
- `contracts/`：内部数据交接约定。
- `runtime/`：本项目实际考试数据与管理员配置，不提交 Git。
- `.venv/`、根目录 `node_modules/` 与 `services/results/node_modules/`：本项目独立安装的开发依赖，不提交 Git。
- `.local/`：日志、工具配置及迁移前历史备份，不提交 Git。

## 从源码恢复

macOS 开发环境需要 Python 3.12 和 Node.js 22.13 或以上版本；本机验证版本记录在 `.python-version` 与 `.node-version`。以下为 macOS 开发入口；Windows 构建环境与命令见 [Windows 桌面预览版](docs/windows-desktop.md)。

```sh
npm run setup
npm run check
npm test
npm run test:review-ui
npm run desktop:build
```

`setup` 根据本项目的依赖清单安装到根目录 `.venv` 和结果模块自己的 `node_modules`，不借用其他项目环境。可用 `JOY_PYTHON_BOOTSTRAP` 指定 Python 3.12 的解释器位置。

`test:review-ui` 使用虚构名单、答题卡和临时运行目录，验证 75%、100%、110% 缩放下的单题保存、连续修正、键盘提交、审计记录及导出状态，同时检查考号与原卷并列、基础信息只显示一次、S 学号确认、漏名单补全和仅考号异常的考卷。多卷场景还验证“完成并收起本张”定位到第一张未完成且仍展开的考卷，保持手动折叠状态，全部完成后定位到导出区，并保留其他考卷的未保存输入。默认使用本机 Chrome；也可通过 `JOY_BROWSER_EXECUTABLE` 指定 Chromium 浏览器可执行文件。

已有 `runtime/.dev.vars` 和考试数据会保留。新环境首次安装时自动生成独立管理员配置，登录资料保存在 `runtime/.local/admin-login.txt`。

## 启动与构建

`npm run start` 启动本机两个服务，阅卷端口 `8510`、结果端口 `3010`，均监听 `127.0.0.1`。双击 `output/佳音考试管理.app` 则由原生窗口承载同一服务。关闭 App 后结束由该 App 启动的服务。

macOS 的 `desktop:build` 当前仍生成供本机开发与验收使用的 App，依赖本项目目录和本机的 Python/Node 基础解释器。其他 Mac 的完整运行环境封装、签名和公证属于后续发布工作；现有 macOS 开发 ZIP 保持这一适用范围。

Windows 的构建入口为 `npm run desktop:build:windows`，需在 Windows x64 环境运行，生成内置运行环境的安装程序和 ZIP 包，输出到 `output/windows/`。当前版本为 2.1.0-beta.2 预览版，实际 Win10/11 人工验收待进行。Windows 源码安装及构建命令见 [Windows 桌面预览版](docs/windows-desktop.md)。

Windows 应用数据按账户独立保存在 `%APPDATA%\佳音考试管理\runtime`，卸载会保留数据；原始照片仍保存在用户选择的目录，备份时应与运行数据、已导出文件一并保存。日志位于该数据目录的 `logs\desktop.log`，可从窗口“数据目录”打开。

源码目录移动后，重新运行安装和构建；Python 虚拟环境本身不作为可搬运的安装包。

“完成并收起本张”会定位到第一张未完成且仍展开的考卷，手动折叠的考卷保持折叠；若剩余待复核考卷都已折叠，会提示手动展开继续审核。全部完成后定位到导出区。最新修复与验证记录见 `docs/手动折叠状态修复_2026-10-02.md`，此前记录见 `docs/完成收起定位修复_2026-10-02.md`。

恢复复核进度或更新当前页面时，已保存的人工答案和 Part 分数优先于原图的空白候选，不会重新进入待复核队列；部分完成的 Part 只保留尚未确认的题目。“逐题检查”提示按实际待检查题数显示。当前会话中保留的已完成表单标明“原始识别（已复核）”。说明见 `docs/已复核空白候选修复_2026-10-03.md`。

复核页面固定恢复提示、图片概览、考号核对及答题核对区域的位置，每题整套内容在同一替换槽内更新；整 Part 确认或展开使用按钮回调完成一次局部刷新，减少残留灰色表单。原有答案控件键及手动折叠状态继续保留。说明见 `docs/复核表单残留修复_2026-10-03.md`。

空白 Part 的“逐题检查”定位到当前 Part 第一道待确认题目；展开前保护该 Part 的当前位置，展开后不回到基础信息区。若该 Part 已全部确认，则定位到当前考卷的答题核对提示。“完成并收起本张”继续使用已确认的待复核考卷定位规则。说明见 `docs/逐题展开定位修复_2026-10-04.md`。

所有客观题审核标题及保存提示显示 Part 名称、完整题号范围和当前题号，例如 `Written Part7 （36～42） 题号36`。范围读取当前答题卡模板，不因部分题目已经完成而缩小。说明见 `docs/单题Part信息补充_2026-10-04.md`。

“🔍 界面缩放”固定在右上角 Deploy 所在工具栏旁，滚动到任意位置均可使用。保留 75%、85%、100%、110% 比例，仅缩放正文；按钮和顶部工具栏保持原有大小。说明见 `docs/固定界面缩放入口_2026-10-04.md`。

结果管理的导出区依次提供 PDF、六维系数名单（运营存档）、详细得分名单（教学备份）。运营存档仅含 Sheet1 的名单信息、六维系数和精修笔试通过情况；教学备份保留完整分数明细及附表。Excel 默认文件名采用阅卷时导入的原名单名称，去掉扩展名和重复的导出后缀，再加“六维系数”或“详细得分”，例如 `学业水平测试统计名单-0930KDTKL六维系数.xlsx`。历史批次可在导出区补填原名。说明见 `docs/教学备份与运营存档导出_2026-10-04.md`。

“学生预览”的报告默认横向排列，可左右滚动查看，也可切换为竖向排列。预览首尾各有一个同步的“展开／折叠”按钮；从末尾折叠会回到预览开头。本次管理页面内查询其他学生时保留所选排列方式，新查询的报告自动展开。说明见 `docs/学生预览折叠与排列_2026-10-04.md`。
