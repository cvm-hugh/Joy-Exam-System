# V2.0 代码整理

## 阅卷操作与页面分离

- 新增 `services/scanner/app/review_session.py`，集中 17 个阅卷状态操作：初始化、进度保存、操作人确认、审计记录、状态同步、考号确认、后补学生确认、逐题保存、整 Part 确认与展开、折叠状态和导航目标。
- `scan_ui.py` 保留原回调名称和参数，通过当前 `st.session_state` 映射调用这些操作；不缓存其他用户或其他页面会话的状态。
- 5 处重复的状态更新、导出缓存失效、进度保存统一使用 `save_record_update`，操作顺序保持一致。
- 原图保存监视器显式接收模板和名单，减少对页面模块全局变量的依赖。
- 页面代码由 1211 行减至 977 行，页面内的 176 处直接 Streamlit 渲染调用经静态语法比较保持一致。
- 搬移操作先经 AST 静态结构比较，确认状态访问和操作调用转换后的结构一致；格式整理恢复原注释，并再次进行 AST 比较。

## 结果管理

- `api-http.ts` 集中请求体大小限制、JSON 解析、响应头、API 错误以及图片文件头识别。接口路由、鉴权和数据库事务保留在原位置。
- `roster-export.ts` 集中名单列定义、元数据取值、信息附表和工作表样式；导出列位置从列定义推导。
- 六维数据使用固定维度编号匹配，名单列标题沿用已有名称，避免显示名称编辑影响系数取值。
- 每次导出预先建立 Part 索引并计算维度满分；每名学生仅计算实际得分和截断系数。
- `export-file-name.ts` 独立处理导出名称，原模块保留导出入口。UTF-8 文件名长度使用累计字节计算。
- API 文件由 861 行减至 779 行，系数导出主文件由 284 行减至 190 行。

## 静态检查

- `npm run check` 新增项目自有 Python 解释器的源码编译检查，只在内存中编译源文件，不导入或执行应用、不生成字节码、不写入考试数据。
- TypeScript 类型检查、lint 和源码独立性检查继续使用原入口。
- 本轮未新增、修改或运行测试，未通过真实考试数据验证操作流程。此前发现的详细得分工作表数量测试预期仍需在后续回归验证阶段同步。
