# 复核表单残留修复

日期：2026-10-03；基于唯一维护主线 `12e3e17`。

## 用户现象

重新打开 App 后，同一题目出现三套“真实填涂／保存该项修正”控件，上面两套为灰色，最下面一套可用。用户确认停留几秒后仍然存在。

## 排查依据与限制

- 源码每个复核项目只生成一个单题表单，表单和答案控件键均包含图片来源及题目键；日志未见本轮启动后的重复表单注册异常。
- 恢复进度提示原先只在首次恢复时写入页面；随后整页更新时该提示消失，改变局部刷新函数的入口位置。局部刷新身份依赖入口位置，因此这种变化会改变刷新边界。
- 考号核对的条件内容、空白警告和逐题展开提示也会改变后续控件的位置。整 Part 操作原先还会在绘制中途强制 `st.rerun()`，中断当前局部刷新并发起一次整页刷新。
- 截图与旧表单残留一致。本轮未通过界面操作复现，不能断言已定位框架层面的全部原因，也不能由灰色控件推断保存记录重复。

## 改动

- 恢复提示和扫描进度始终占用固定槽位，减少整页更新时局部刷新入口变化。
- 图片概览、考号核对和答题核对使用固定容器，题目前的三类提示使用固定槽位。
- 每道题或整 Part 的整套内容放在一个替换槽中，包含标题、原图、保存状态及唯一表单。
- 整 Part 确认和逐题展开改为按钮回调，在当前局部刷新开始前更新状态和保存进度；不在绘制中途额外重跑整页。
- 保留原有答案、单题表单、滚动锚点和考卷折叠控件键。未重置其他题目的输入状态；保存后仍保留当前已完成表单供修改，点击“完成并收起本张”才退出展示。
- 已确认整 Part 的重复确认回调直接返回，避免快速重复点击额外写入人工确认审计。

候选规则、识别算法、评分公式和成绩导出格式沿用现有主线。整 Part 确认继续使用既有人工确认和审计逻辑；展开继续保留已保存分数，只生成待检查题目。

## 检查范围

本轮进行 Python 语法、源码独立性、TypeScript 类型、代码规则和 Git 差异检查，重新构建本机 App。未新增或运行自动化测试，未进行界面操作复测，未启动 App 或操作真实名单、答题卡、成绩或复核进度。

检查结果：修改后的 Python 源文件语法通过；源码独立性检查覆盖 178 个源码及配置文件，通过；TypeScript 类型、代码规则和 Git 差异检查通过；本机 App 构建与签名检查通过。项目 `runtime/` 及 Application Support 中的阅卷数据文件摘要与本轮修改前一致。
