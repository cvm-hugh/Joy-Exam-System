# 佳音考试管理：独立维护主线

用户于 2026-10-02 确认“佳音考试管理”为唯一后续维护主线，并要求补齐源代码与环境，停止共用旧项目依赖。

## 原状态与处理

- 两个服务已有完整的 Git 跟踪源码，没有发现被 Git 记录为删除的源码文件。
- 结果端 `node_modules` 是失效的旧工作区软链接；现改为根据锁文件在本项目内重新安装。
- 阅卷端借用旧项目 Python 虚拟环境，且没有自己的 Python 依赖清单；现补齐直接依赖与锁定清单，在合并根目录创建独立 `.venv`。
- 统一启动脚本及结果端旧桌面脚本写死了旧工作区路径；现按脚本位置、本项目开发配置定位，旧入口统一转发到合并根目录。
- 管理员初始化脚本现支持指定运行目录，保留既有配置，仅在全新环境中生成新凭证。
- 阅卷模块在未设置运行目录时，默认使用“佳音考试管理”的用户数据目录，避免直接启动模块时与旧独立 App 共用数据。
- 三个用于特定 Excel 样本的临时分析脚本依赖未声明的专用制表运行时，与产品构建无关；原文保存在 `docs/history/english-filter/`，停止作为产品可执行入口。旧独立 App 启动源码、PyInstaller 配置和两项一次性数据修补工具也已原文归档；兼容入口统一打开或构建“佳音考试管理”。
- 两个旧服务仓库的完整 Git 元数据、bundle 和未提交改动补丁保存在 `.local/git-history/`。统一根目录使用自己的仓库，源码作为普通文件纳入同一版本，而不是 Git 子模块。

## 开发环境边界

本次独立化完成源码、依赖和本机开发流程的分离。Python 和 Node 的基础解释器仍由开发机器提供；它们不来自旧项目虚拟环境。移植到其他电脑的完整运行环境与 Windows 桌面适配仍需单独构建、验收。

实际考试数据只保留在原 `runtime/` 中，本次不替换批次、不更新管理员口令。源码仓库和构建 App 均排除这类数据。
